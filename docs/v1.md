## 1. 项目背景

在 Go 后端项目中，通常使用 Protobuf 定义 API 接口，并通过 `google.api.http` annotations 将 gRPC 服务映射为 HTTP REST API。

例如：

```proto
syntax = "proto3";

package user.v1;

import "google/api/annotations.proto";

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse) {
    option (google.api.http) = {
      get: "/v1/users/{id}"
    };
  }

  rpc CreateUser(CreateUserRequest) returns (CreateUserResponse) {
    option (google.api.http) = {
      post: "/v1/users"
      body: "*"
    };
  }
}

message GetUserRequest {
  string id = 1;
}

message GetUserResponse {
  string id = 1;
  string name = 2;
}

message CreateUserRequest {
  string name = 1;
}

message CreateUserResponse {
  string id = 1;
  string name = 2;
}
```

后端通过 gRPC-Gateway 提供 HTTP 服务，前端则需要根据同一份 Proto 定义生成对应的 TypeScript 类型、HTTP API Client 和 React Query Hooks。

项目希望实现一套完整的代码生成工具链：

```
                 Protobuf
                    |
             google.api.http
                    |
                    v
          CodeGeneratorRequest
                    |
          +---------+---------+
          |         |         |
          v         v         v
     TypeScript   Axios    React Query
      Plugin      Plugin     Plugin
          |         |         |
          v         v         v
       Types     API Client  Hooks
          |         |         |
          +---------+---------+
                    |
                    v
              Frontend SDK
```

核心目标：

1. 使用 Protobuf 作为前后端 API 契约的唯一来源。
2. 自动生成符合 protojson 形态的 TypeScript 类型。
3. 根据 `google.api.http` annotations 自动生成与 grpc-gateway 语义兼容的 Axios HTTP Client。
4. 自动生成 TanStack React Query Hooks。
5. 支持 Buf 和 Bazel 两种代码生成工作流。
6. 保证生成结果可预测、可复现，适合 CI 和大型项目。

## 2. 总体架构

### 2.1 插件组成

| 插件                                  | 职责                   | 依赖               |
| ------------------------------------- | ---------------------- | ------------------ |
| `protoc-gen-grpc-gateway-typescript`  | 生成 TypeScript 类型   | 无                 |
| `protoc-gen-grpc-gateway-axios`       | 生成 Axios API Client  | TypeScript         |
| `protoc-gen-grpc-gateway-react-query` | 生成 React Query Hooks | TypeScript + Axios |

另外提供：

- `grpc-gateway-typescript.bzl`：Bazel 规则与工具链集成。
- `buf.gen.yaml`：Buf 多插件生成配置。
- 共享内部代码：Proto Descriptor 解析、共享 IR、HTTP Annotation 解析、命名转换、文件输出等。

### 2.2 插件依赖关系

```
flowchart TD
    Proto[Protobuf Definitions]

    Proto --> TS[protoc-gen-grpc-gateway-typescript]
    Proto --> Axios[protoc-gen-grpc-gateway-axios]
    Proto --> RQ[protoc-gen-grpc-gateway-react-query]

    TS --> Types[TypeScript Types]
    Axios --> Client[Axios API Client]
    RQ --> Hooks[React Query Hooks]

    Types --> Client
    Types --> Hooks
    Client --> Hooks
```

这里的依赖关系必须区分清楚：

1. **生成代码依赖**：Axios 生成的文件 `import type` TypeScript 类型；React Query 生成的文件 `import type` 类型并 `import type` Axios Client。
2. **生成执行依赖**：**不存在**。三个插件都只读取同一份 Proto Descriptor，通过命名契约生成固定的 import 路径，不读取彼此的输出。
3. **编译依赖**：三个产物都生成后，才能一起通过 TypeScript 编译。

因此：

- Buf 可以在同一次生成流程中执行多个插件，插件执行顺序不影响结果。
- Bazel 中三个生成 action 可以是并行的兄弟 action，不需要串行依赖；组合 rule 负责聚合输出。
- 三个插件必须共享**完全一致的文件命名、字段命名和 import 路径规则**。

### 2.3 生成契约（新增，必须首先定死）

三个插件之间最容易返工的不是 Proto 解析，而是生成契约。v1.1 固定以下约定。

#### 文件命名

对每个 `file_to_generate` 中的 proto 文件，`<base>` 为去掉 `.proto` 后的路径：

- `user/v1/user.proto` → `<base>` = `user/v1/user`
- 类型文件：`user/v1/user_pb.ts`
- Axios 文件：`user/v1/user_api.ts`
- React Query 文件：`user/v1/user_react_query.ts`

默认后缀：

| 文件 | 默认后缀 |
| --- | --- |
| 类型 | `_pb.ts` |
| Axios | `_api.ts` |
| React Query | `_react_query.ts` |

三个插件都接受同一组契约参数，即使某个插件只使用其中一部分：

```
types_suffix=_pb.ts
api_suffix=_api.ts
query_suffix=_react_query.ts
import_extension=.js
use_proto_names=false
```

如果用户自定义后缀，必须在三个插件上同时配置；否则 import 会断。

`_pb.ts` 与 protoc-gen-es 的默认命名相同。如果项目同时使用 protoc-gen-es，建议把 `types_suffix` 改为 `.types.ts` 之类的值。

#### 稳定产出

为了 Bazel 能在 action 执行前声明输出，建议：

- 对每个 `file_to_generate` 都生成三个文件；
- 没有内容时生成只含 header 注释的文件；
- 提供 `empty_files=emit|skip` 选项，Buf 用户可以选择 `skip`，Bazel 规则固定使用 `emit`。

#### 生成文件头

每个文件包含：

```
// Code generated by <plugin-name>. DO NOT EDIT.
// @grpc-gateway-typescript-contract: v1
// source: user/v1/user.proto
```

不包含时间戳、绝对路径等不稳定信息。

#### 类型引用与 import

- 同文件内直接使用类型名。
- 其他 proto 文件使用 namespace import：

```ts
import type * as user_v1_address_pb from "./address_pb";
// ...
address: user_v1_address_pb.Address;
```

namespace import 能避免两个文件导出同名类型时冲突。alias 由 proto path 确定性生成（非字母数字替换为 `_`）。

- 外部依赖通过 `M` 映射指定模块路径，格式与 protoc-gen-go 一致：

```
Mgoogle/type/money.proto=@acme/grpc-types/google/type/money
Mcompany/common/v1/common.proto=@acme/grpc-types/company/common/v1/common
```

没有映射时回退到相对路径，并在生成文件里写注释提示可能缺失。

- Well-known types 直接内联为 TS 基础类型，不生成、不 import `google/protobuf/*`。
- 永远跳过 `google/protobuf/*`、`google/api/annotations.proto`、`google/api/http.proto` 的代码生成，即使它们出现在 `file_to_generate` 中（例如 Buf 开启了 `include_imports`）。
- `import_extension=.js` 只追加在相对 import 上，不追加在包名 import 上。

#### 字段命名

- 默认使用 `json_name`（lowerCamelCase），与 protojson 默认行为一致。
- 提供 `use_proto_names=true` 对齐 protojson 的 `UseProtoNames`。
- 该选项必须三插件共享。protojson 解码时同时接受 proto 名和 JSON 名，所以请求侧是安全的；但响应侧的字段名取决于网关 marshaler 的配置，使用 `use_proto_names` 时需要与网关保持一致。

## 3. 插件一：TypeScript 类型生成

### 3.1 项目名称

`protoc-gen-grpc-gateway-typescript`

### 3.2 职责

只负责将 Protobuf Message / Enum 转换为 TypeScript 类型定义。

不负责：

- HTTP 请求。
- Axios 实例。
- Fetch 实现。
- React Query。
- API URL 生成。
- 参数校验。
- 运行时序列化逻辑。

它是整个 SDK 的基础层。

### 3.3 输入

标准 Protoc 插件输入：

- `CodeGeneratorRequest`
- Proto FileDescriptor
- Message Descriptor
- Enum Descriptor
- Service Descriptor（只用于确定文件是否有 service，不生成类型）
- `google.api.field_behavior`（可选，后续用于 required 标记）

### 3.4 输出

```
gen/
└── user/
    └── v1/
        ├── user_pb.ts
        ├── user_api.ts
        └── user_react_query.ts
```

其中 `user_pb.ts` 只放置 Message、Enum、oneof、WKT 辅助类型。

示例：

```ts
export type GetUserRequest = {
  id?: string;
};

export type GetUserResponse = {
  id?: string;
  name?: string;
};

export type CreateUserRequest = {
  name?: string;
};

export type CreateUserResponse = {
  id?: string;
  name?: string;
};
```

> v1.0 的 §3.4 输出示例里出现了 `user_connect.ts`，这是笔误，已修正为 `_api.ts` / `_react_query.ts`。

### 3.5 类型映射矩阵（必须完整实现）

| Proto 类型 | 默认 TypeScript | 说明 |
| --- | --- | --- |
| `double` / `float` | `number` | JSON 的 `NaN`/`Infinity` 是字符串，v1 不支持特殊值 |
| `int32` / `uint32` / `sint32` / `fixed32` / `sfixed32` | `number` | |
| `int64` / `uint64` / `sint64` / `fixed64` / `sfixed64` | `string` | 与 protojson 一致，避免精度问题 |
| `bool` | `boolean` | |
| `string` | `string` | |
| `bytes` | `string` | base64，与 protojson 一致 |
| `enum` | 字符串字面量联合 | 默认 `enum_style=union` |
| `message` | 具名 type | |
| `repeated T` | `T[]` | |
| `map<K,V>` | `Record<string, V>` | **JSON 的 key 永远是 string** |
| `optional` | `field?: T` | |
| `oneof` | 互斥联合 | 见 §3.7 |
| `google.protobuf.Timestamp` | `string` | RFC3339 |
| `google.protobuf.Duration` | `string` | 例如 `"3.5s"` |
| `google.protobuf.FieldMask` | `string` | 逗号分隔的路径 |
| `google.protobuf.Struct` | `Record<string, JsonValue>` | |
| `google.protobuf.Value` | `JsonValue` | |
| `google.protobuf.ListValue` | `JsonValue[]` | |
| `google.protobuf.Empty` | `Record<string, never>` | |
| `google.protobuf.Any` | `{ "@type": string; [key: string]: unknown }` | |
| `google.protobuf.*Value`（wrappers） | `T \| null` | 数值类为 `number \| null`，字符串/bytes 为 `string \| null`，bool 为 `boolean \| null` |
| `google.protobuf.NullValue` | `null` | |

`JsonValue` 在每个需要的文件中定义一次（不导出也可以）：

```ts
type JsonValue =
  | null
  | boolean
  | number
  | string
  | JsonValue[]
  | { [key: string]: JsonValue };
```

#### 64 位整数策略

- 默认 `long_type=string`。
- 可选 `long_type=number`，但必须在文档中标注精度风险（超过 `Number.MAX_SAFE_INTEGER` 会丢精度）。
- `long_type=bigint` **v1 不实现**。原因：
  - React Query 的 query key 使用 `JSON.stringify` 做稳定哈希，`BigInt` 会直接抛错；
  - Axios 请求体需要自定义 `replacer`，响应需要 `reviver`；
  - 会显著增加生成代码的运行时逻辑。
- 后续如果支持 `bigint`，必须同时解决 query key 序列化和请求/响应转换。

#### bytes 策略

- 默认 `bytes_type=string`（base64），与 protojson 直接兼容。
- `bytes_type=Uint8Array` 放到后续版本；它需要请求体 base64 replacer、响应解码，以及 query 编码时单独处理。

### 3.6 字段可选性与默认值

- 所有 singular 字段默认生成 `field?: T`。
- 不区分 proto3 普通字段和 `optional` 字段；两者都用 `?:`。
- `proto3 optional` 会生成 synthetic oneof，必须排除，不能当成业务 oneof 处理。
- proto3 的默认值语义由网关处理；客户端只需要区分“未设置”和“显式设置为 0 / false / ""”。

### 3.7 oneof

默认生成互斥联合类型，而不是扁平可选字段：

```ts
export type Payment =
  | { card: Card; bank?: never; cash?: never }
  | { bank: Bank; card?: never; cash?: never }
  | { cash: Cash; card?: never; bank?: never };
```

- 每个成员都带上其他成员的 `?: never`，在类型层面阻止同时设置两个成员。
- JSON 形态仍是扁平的，符合 protojson。
- 成员很多时文本量是 O(n²)，但可读性好、无需运行时辅助类型。
- 提供 `oneof_style=flat` 回退为扁平可选字段（仅用于特殊场景）。
- synthetic oneof（`proto3 optional`）不参与生成。

### 3.8 enum

默认 `enum_style=union`：

```ts
export type UserStatus =
  | "USER_STATUS_UNSPECIFIED"
  | "ACTIVE"
  | "DISABLED";
```

可选 `enum_style=const`：

```ts
export const UserStatus = {
  USER_STATUS_UNSPECIFIED: "USER_STATUS_UNSPECIFIED",
  ACTIVE: "ACTIVE",
  DISABLED: "DISABLED",
} as const;

export type UserStatus = (typeof UserStatus)[keyof typeof UserStatus];
```

可选 `enum_style=enum`：

```ts
export enum UserStatus {
  USER_STATUS_UNSPECIFIED = "USER_STATUS_UNSPECIFIED",
  ACTIVE = "ACTIVE",
  DISABLED = "DISABLED",
}
```

说明：

- protojson 使用枚举名，所以字符串枚举是正确的 wire 形态。
- `allow_alias` 时保留所有名字；union 天然去重，const 对象的 key 不冲突。
- 单值枚举也生成联合类型，不要特殊化成单个字面量类型（便于后续加值）。

### 3.9 嵌套类型命名

- Message：`Outer_Inner`
- Enum：`Outer_Inner_Status`
- 与顶层类型重名时，使用更长的分隔或检测报错；默认分隔符为 `_`。
- 提供 `nested_name_separator` 选项，默认 `_`。

### 3.10 注释

- 读取 proto 的 leading comments，生成 JSDoc 注释。
- 字段注释放在字段上方。
- 不生成随机的、依赖运行环境的注释。

### 3.11 设计要求

1. 生成结果不依赖 Axios、React Query 等第三方 HTTP 库。
2. 支持跨文件 Message 引用（namespace import）。
3. 支持 Proto package / file path 到输出目录的映射。
4. 支持自定义后缀和 import 扩展名。
5. 生成文件具有稳定的 import 路径。
6. 不生成没有必要的运行时逻辑（默认 `enum_style=union`）。
7. 生成代码在 `strict` 下可以编译，不使用 `@ts-nocheck`。
8. 输出稳定：声明顺序按 proto 顺序，import 排序确定。

## 4. 插件二：Axios API Client 生成

### 4.1 项目名称

`protoc-gen-grpc-gateway-axios`

### 4.2 职责

根据 Protobuf Service 和 `google.api.http` annotations 自动生成 Axios HTTP API Client。

这是整个工具链中负责 HTTP API 实现的插件。

### 4.3 输入

读取：

- Service Descriptor
- RPC Method Descriptor
- Request / Response Message Descriptor
- `google.api.http` annotations
- 共享 IR（由共享包构建）

### 4.4 输出

```
gen/
└── user/
    └── v1/
        ├── user_pb.ts
        ├── user_api.ts
        └── user_react_query.ts
```

### 4.5 支持的 HTTP Annotation

必须支持：

- `get`
- `post`
- `put`
- `patch`
- `delete`
- `custom`（任意 kind + path）
- `body`
- `response_body`
- `additional_bindings`（默认只生成 primary，见 §4.11）
- path 模板中的 `:verb` 后缀
- path 变量 `{id}` 与 `{name=shippers/*}` / `{name=**}`

### 4.6 生成代码示例

Proto：

```proto
rpc GetUser(GetUserRequest) returns (GetUserResponse) {
  option (google.api.http) = {
    get: "/v1/users/{id}"
  };
}
```

生成：

```ts
import type { AxiosInstance, AxiosRequestConfig } from "axios";
import type { GetUserRequest, GetUserResponse } from "./user_pb";

export class UserServiceClient {
  constructor(private readonly http: AxiosInstance) {}

  getUser(
    request: GetUserRequest,
    config?: AxiosRequestConfig,
  ): Promise<GetUserResponse> {
    if (request.id == null) {
      throw new Error("missing required field: id");
    }
    const url = `/v1/users/${encodeURIComponent(String(request.id))}`;
    return this.http
      .request<GetUserResponse>({
        ...config,
        url,
        method: "GET",
      })
      .then((response) => response.data);
  }
}
```

要点：

- 方法接受 `AxiosRequestConfig`，用于 headers、timeout、`signal` 等。
- 生成代码不创建 Axios 实例。
- `url`、`method`、`data` 在合并时放在 `config` 之后，避免用户误覆盖。
- 返回值已经解包 `response.data`。

### 4.7 URL Path 参数

#### 单段变量 `{id}`

默认等价于 `{id=*}`，值必须是单段：

```ts
const url = `/v1/users/${encodeURIComponent(String(request.id))}`;
```

#### 多段变量 `{name=shippers/*}` / `{name=**}`

值本身包含 `/`，**不能整体 encode**，否则 `shippers/123` 会变成 `shippers%2F123`，gateway 按单段匹配会失败。按段编码：

```ts
const encodePathSegments = (v: unknown) =>
  String(v).split("/").map(encodeURIComponent).join("/");

const url = `/v1/${encodePathSegments(request.name)}`;
```

#### 存在性校验

- 只校验 `== null`，不能使用 `if (!request.id)`，否则 `0`、`false` 会被误判为缺失。
- 嵌套字段使用可选链判断，例如 `request.shipper?.name == null`。

#### path 字面量与 verb

- 字面量原样输出。
- `:verb` 后缀保留，例如 `/v1/users/{id}:activate`。

### 4.8 Query 参数（重点）

**不能**直接写：

```ts
this.http.get("/v1/users", { params: request }); // 错误
```

Axios 默认序列化与 grpc-gateway 不兼容。必须按以下规则生成显式代码。

#### 编码规则

| Proto 类型 | Query 编码 |
| --- | --- |
| string | 原样 |
| bool | `true` / `false` |
| int32 / uint32 / float / double | 十进制 |
| int64 / uint64 / fixed64 / sfixed64 / sint64 | 十进制字符串（默认 string 映射） |
| bytes | base64 字符串 |
| enum | **枚举名**（gateway 也接受数字，但客户端应发名字） |
| Timestamp | RFC3339Nano 字符串 |
| Duration | 例如 `"3.5s"` |
| FieldMask | 逗号分隔的路径字符串 |
| repeated T | 同名重复参数：`ids=1&ids=2` |
| message | 递归展开：`filter.status=ACTIVE` |
| map<K,V> | **`labels[key]=value`**，key 和 value 都 URL 编码 |
| oneof | 当前设置的成员按普通字段编码 |
| optional | 仅当值不是 `null` / `undefined` 时发送 |

#### 排除规则

1. **path 已绑定的字段必须从 query 中排除**，并排除其后代字段。
2. **body 覆盖的字段必须从 query 中排除**。
   - `body: "*"`：不生成任何 query 参数。
   - `body: "user"`：排除 `user` 及其所有后代。
   - `body: "user.profile"`：只排除 `user.profile` 及其后代，`user.name` 仍可作为 query。
3. **不能用 truthiness 判断**。`0`、`false`、`""` 都是合法值，应该发送；只有 `undefined` / `null` 才省略。

#### 生成示例

```ts
listUsers(
  request: ListUsersRequest,
  config?: AxiosRequestConfig,
): Promise<ListUsersResponse> {
  const query = new URLSearchParams();

  if (request.page != null) {
    query.append("page", String(request.page));
  }
  if (request.pageSize != null) {
    query.append("pageSize", String(request.pageSize));
  }
  if (request.keyword != null) {
    query.append("keyword", request.keyword);
  }
  if (request.filter?.status != null) {
    query.append("filter.status", String(request.filter.status));
  }
  (request.ids ?? []).forEach((v) => {
    query.append("ids", String(v));
  });
  Object.entries(request.labels ?? {}).forEach(([k, v]) => {
    query.append(`labels[${k}]`, String(v));
  });

  const qs = query.toString();
  const url = `/v1/users${qs ? `?${qs}` : ""}`;

  return this.http
    .request<ListUsersResponse>({
      ...config,
      url,
      method: "GET",
    })
    .then((response) => response.data);
}
```

使用 `URLSearchParams` 的原因：

- 它负责 URL 编码；
- 它是浏览器和 Node 18+ 的标准 API；
- 不需要 Axios 全局 `paramsSerializer`；
- 生成代码可读、可调试；
- 不需要共享 runtime 文件（对 Bazel 友好）。

#### map 编码说明

gateway 解析 `labels[key]=value` 时，会把 key 和 value 都作为值处理。生成端必须写成：

```ts
query.append(`labels[${k}]`, String(v));
```

不要写成 `labels.${k}=${v}`。

### 4.9 Body

- `body: ""`：不发送 body。
- `body: "*"`：发送完整 request。
- `body: "user"`：发送 `request.user`。
- `body: "user.profile"`：发送 `request.user?.profile`，注意空值传播。

示例：

```ts
const data = request.user; // body: "user"
return this.http
  .request<CreateUserResponse>({
    ...config,
    url: "/v1/users",
    method: "POST",
    data,
  })
  .then((response) => response.data);
```

不要生成 `request["user.profile"]` 这样的错误访问。

### 4.10 `response_body`

gateway 在写响应时只输出 response message 的指定字段。生成端必须：

1. 把返回类型改成该字段的类型；
2. 解包 `response.data` 的对应字段。

示例：

```proto
rpc GetUser(GetUserRequest) returns (GetUserResponse) {
  option (google.api.http) = {
    get: "/v1/users/{id}"
    response_body: "user"
  };
}

message GetUserResponse {
  User user = 1;
}
```

生成：

```ts
getUser(
  request: GetUserRequest,
  config?: AxiosRequestConfig,
): Promise<User> {
  // ...
  return this.http
    .request<GetUserResponse>({ ...config, url, method: "GET" })
    .then((response) => response.data.user);
}
```

这个信息必须进入共享 IR，React Query 插件才能生成正确的 data 类型。

### 4.11 `additional_bindings`

`google.api.http` 允许一个 RPC 有多个 HTTP 绑定。gateway 服务端会为每个绑定注册路由。

策略：

- **默认只生成 primary binding**。额外绑定通常是为旧客户端保留的别名，新 SDK 调用主路由即可。
- 提供 `additional_bindings=methods` 选项，开启后为每个额外绑定生成方法。
- 命名必须确定，且 Axios 与 React Query 共享：
  - primary：`getUser`
  - 第 2 个绑定：`getUserBinding2`
  - 第 3 个绑定：`getUserBinding3`
- 每个绑定有自己的 `body`、`response_body`、path/query 规则，不能复用 primary 的。
- `additional_bindings` 不能嵌套，解析时忽略嵌套。

### 4.12 无 HTTP Rule / 流式方法

- 没有 `google.api.http` 的方法默认跳过，并在输出文件里写注释。
- `strict_http=true` 时直接报错。
- v1 只支持 unary：
  - server-streaming / client-streaming / bidi 默认跳过并写注释；
  - `streaming=error` 时直接报错；
  - 不要静默生成一个错误的 unary 方法。

### 4.13 Client 形态

默认 `client_style=class`：

```ts
export class UserServiceClient {
  constructor(private readonly http: AxiosInstance) {}
}
```

可选 `client_style=functions`：

```ts
export function getUser(
  http: AxiosInstance,
  request: GetUserRequest,
  config?: AxiosRequestConfig,
): Promise<GetUserResponse> {
  // ...
}
```

### 4.14 Axios 实例设计

生成的 Client 不应自己创建 Axios 实例。由业务项目负责创建和配置：

```ts
import axios from "axios";
import { UserServiceClient } from "./gen/user/v1/user_api";

const http = axios.create({
  baseURL: "/api",
  timeout: 10000,
});

export const userClient = new UserServiceClient(http);
```

这样可以统一处理：

- Base URL
- 请求拦截器
- 响应拦截器
- Token
- 超时
- 错误处理
- 多环境配置
- 请求取消

说明：Axios 的 `baseURL` 与以 `/` 开头的 `url` 会按 `combineURLs` 规则拼接，`baseURL: "/api"` + `url: "/v1/users"` 得到 `/api/v1/users`。

### 4.15 生成的私有 helper

为了 Bazel 的 action 相互独立，v1 不生成共享 runtime 文件。每个 `_api.ts` 内联需要的私有 helper：

- `encodePathSegments`（仅当存在多段 path 变量时生成）
- 其他 query/body 逻辑直接生成语句，不抽公共文件

代价是少量重复代码，收益是：

- 每个文件自包含；
- 多个 Bazel target 不会争抢同一个输出路径；
- action 完全并行；
- tree-shaking 更简单。

如果后续确实需要共享 runtime，再通过 `runtime_dir` 选项显式放到 target 专属目录。

### 4.16 设计要求

1. 生成 Client 必须依赖 Axios。
2. 不创建全局 Axios 实例。
3. 不内置业务层错误处理；非 2xx 由 Axios reject。
4. 支持 Path、Query、Body、Response Body 映射。
5. 正确处理 `additional_bindings`（默认 primary，可选生成额外方法）。
6. 支持 HTTP Method 和 URL 的完整映射。
7. Request / Response 类型必须引用 TypeScript 插件生成的类型。
8. 生成文件不能依赖 React 或 React Query。
9. 方法必须支持 `AxiosRequestConfig`，以便取消和透传配置。
10. 生成代码不使用 `@ts-nocheck`。

## 5. 插件三：React Query Hooks 生成

### 5.1 项目名称

`protoc-gen-grpc-gateway-react-query`

### 5.2 职责

根据 Proto Service 自动生成 TanStack React Query（v5+）Hooks。

该插件建立在 Axios API Client 之上，为前端提供声明式的数据请求接口。

### 5.3 依赖

- `protoc-gen-grpc-gateway-typescript`
- `protoc-gen-grpc-gateway-axios`
- `@tanstack/react-query` v5+
- React 18+

### 5.4 输出

```
gen/
└── user/
    └── v1/
        ├── user_pb.ts
        ├── user_api.ts
        └── user_react_query.ts
```

### 5.5 Query Key 生成

每个查询方法生成稳定的 key，key 必须包含**完整 request**，不能只放 `request.id`。

```ts
export const userServiceKeys = {
  all: ["userService"] as const,

  getUser: (request: GetUserRequest | undefined) =>
    [...userServiceKeys.all, "getUser", request] as const,

  listUsers: (request: ListUsersRequest) =>
    [...userServiceKeys.all, "listUsers", request] as const,
};
```

要点：

- 按 service 作用域命名（`userServiceKeys`），避免不同 service 的 key 冲突。
- key 工厂必须导出，供用户手动 `invalidateQueries`。
- React Query v5 会对对象 key 做稳定排序哈希；request 里的 `undefined` 字段会被 `JSON.stringify` 忽略，语义上等价于未设置。
- **不要支持 `bigint`**：`JSON.stringify(BigInt)` 会抛错，query key 直接不可用。

### 5.6 Query Hook

```ts
import {
  useQuery,
  type UseQueryOptions,
} from "@tanstack/react-query";
import type { UserServiceClient } from "./user_api";
import type { GetUserRequest, GetUserResponse } from "./user_pb";

export function useGetUser(
  client: UserServiceClient,
  request: GetUserRequest | undefined,
  options?: Omit<
    UseQueryOptions<GetUserResponse, Error>,
    "queryKey" | "queryFn" | "enabled"
  >,
) {
  const { enabled, ...rest } = options ?? {};

  return useQuery({
    ...rest,
    queryKey: userServiceKeys.getUser(request),
    queryFn: ({ signal }) => {
      if (request === undefined) {
        return Promise.reject(new Error("request is required"));
      }
      return client.getUser(request, { signal });
    },
    enabled: enabled ?? request !== undefined,
  });
}
```

要点：

- `request` 允许 `undefined`，默认 `enabled: request !== undefined`，方便“id 还没拿到就不请求”。
- `options` 透传 `select`、`staleTime`、`enabled` 等；但不能覆盖 `queryKey` / `queryFn`。
- 把 React Query 的 `signal` 传给 Axios，页面切换或参数变化时可以取消在途请求。
- 不使用 `@ts-nocheck`，保持 data 类型推导。

### 5.7 Mutation Hook

```ts
import {
  useMutation,
  type UseMutationOptions,
} from "@tanstack/react-query";

export function useCreateUser(
  client: UserServiceClient,
  options?: UseMutationOptions<
    CreateUserResponse,
    Error,
    CreateUserRequest
  >,
) {
  return useMutation({
    ...options,
    mutationFn: (request: CreateUserRequest) =>
      client.createUser(request),
  });
}
```

要点：

- `...options` 放在前面，`mutationFn` 放在后面，避免被覆盖。
- mutation 不需要 `signal`（React Query 不对 mutation 提供取消语义）。

### 5.8 Client 注入方式

通过参数注入 Client：

```ts
const client = new UserServiceClient(http);

const query = useGetUser(client, {
  id: "1001",
});
```

不在生成代码中直接依赖项目的全局 Axios 实例或业务上下文。这样可以：

- 支持多个 API Host。
- 支持不同 Axios 配置。
- 便于测试。
- 避免生成代码与业务应用耦合。
- 方便在不同项目中复用 SDK。

后续可以增加可选的 Provider 版本，但 v1 保持参数注入。

### 5.9 Query 与 Mutation 的判断

默认按 HTTP Method 分类：

| HTTP Method | 默认生成类型 |
| --- | --- |
| GET | Query |
| POST | Mutation |
| PUT | Mutation |
| PATCH | Mutation |
| DELETE | Mutation |
| 其他 / custom | Mutation（除非 kind 是 GET） |

提供覆盖参数：

```
queries=user.v1.UserService.Search,user.v1.UserService.Validate
```

用于处理“POST 但语义上是查询”的接口。

### 5.10 命名冲突

- 同一 proto 文件里多个 service 有同名 method 时，hook 名会冲突（例如两个 `GetUser`）。
- 生成器必须检测：
  - 默认保持 `useGetUser`；
  - 检测到冲突时自动加 service 前缀，例如 `useAdminServiceGetUser`；
  - 或通过 `hook_prefix=service` 强制所有 hook 带 service 前缀。

命名规则必须与 Axios 插件的 `client_style=functions` 模式保持一致（如果使用函数式 Client）。

### 5.11 additional_bindings

如果 Axios 插件开启 `additional_bindings=methods`，React Query 也要为每个 binding 生成：

- hook：`useGetUserBinding2`
- key：`userServiceKeys.getUserBinding2`

否则两个插件的 API 对不上。

### 5.12 第一阶段能力与后续

第一阶段：

- Query Keys
- `useQuery`
- `useMutation`
- Query / Mutation 类型推导
- Client 注入
- `request` 可选 + `enabled`
- `options` 透传
- `signal` 取消

后续：

- 自动生成 invalidate 逻辑
- Query Options 工厂函数
- Mutation Options 工厂函数
- Infinite Query
- Pagination
- 乐观更新
- 自定义 Query Key 前缀
- Provider 版本

不要在 v1 引入过多业务约定。

## 6. 共享内部架构

### 6.1 共享 IR（新增）

三个插件都应消费同一份 IR，而不仅仅是共享 Descriptor 解析。这样可以保证：

- Axios 与 React Query 的 method 名、client 名、binding 后缀一致；
- `response_body` 的返回类型两边一致；
- query 字段列表只计算一次；
- 类型映射只实现一次。

建议的 IR：

```go
package ir

type File struct {
    ProtoPath  string
    Package    string
    OutputBase string
    Messages   []*Message
    Enums      []*Enum
    Services   []*Service
    Imports    []*Import
}

type Service struct {
    Name    string
    Methods []*Method
}

type Method struct {
    Name         string
    ClientName   string // getUser
    Input        *MessageRef
    Output       *MessageRef
    Bindings     []*Binding
    Streaming    bool
    HasHTTPRule  bool
}

type Binding struct {
    HTTPMethod   string
    Template     *httprule.Template
    Body         httprule.FieldPath
    ResponseBody httprule.FieldPath
    QueryFields  []httprule.FieldPath
    IsPrimary    bool
}
```

IR 构建阶段负责：

- 解析 `google.api.http`；
- 计算 path/query/body/response_body；
- 应用 naming 规则；
- 应用类型映射；
- 把错误带上 proto 文件和位置。

模板层只负责把 IR 渲染成 TS，不再做语义判断。

### 6.2 HTTP Rule 解析

建议实现独立的 `internal/httprule`：

- `ParseTemplate`：支持 `/v1/{name=shippers/*}:verb`、`**`、`*`、字面量。
- `FieldPath`：支持 `a.b.c`。
- `Binding`：method、template、body、response_body、additional bindings。
- `QueryFields`：递归收集 leaf 字段，带 path-local 的循环保护。

**不要**照抄参考实现里的全局 `seen` 集合。go-kratos 的实现用全局 `seen`，同一个消息类型出现在两个不同分支时只会展开第一个分支，是 bug。应该用“当前递归路径”的 visited 集合。

### 6.3 命名与契约

`internal/contract` 负责：

- 文件后缀；
- `<base>` 计算；
- 相对 import 路径；
- namespace alias；
- `M` 映射；
- client / method / hook / key 命名；
- `use_proto_names`；
- type name（嵌套 `Outer_Inner`）。

三个插件都必须调用同一套函数。

### 6.4 TypeScript Writer

`internal/ts` 负责：

- 缩进；
- import 收集与排序；
- 注释；
- 生成文件头；
- 空文件 header；
- 稳定输出。

### 6.6 插件入口

```go
func main() {
    var params pluginParams
    opts := protogen.Options{ParamFunc: params.Set}
    gen := opts.New(reqFromStdin())
    gen.SupportedFeatures = uint64(pluginpb.CodeGeneratorResponse_FEATURE_PROTO3_OPTIONAL)
```

注意：

- Proto Descriptor 解析

- HTTP Rule 解析
- TypeScript 命名规则
- Import 路径计算
- 文件后缀契约
- 代码文件写入
- 插件参数解析
- 错误定位

不应该共享：

- Axios Client 生成模板
- React Query Hook 生成模板
- 各插件特有的输出策略

### 6.8 确定性与错误处理

- 不使用 map 迭代决定输出顺序；import 排序；文件内容按 proto 声明顺序。
- 不写入时间戳、绝对路径。
- 错误信息带上 proto 文件、方法名、字段路径。
- 生成失败时返回非零退出码，不写部分输出。

## 8. Bazel 集成

### 8.1 目标

提供 `grpc-gateway-typescript.bzl`，使 Bazel 项目能够使用三个插件生成前端 SDK。

Bazel 集成应满足：

- Hermetic。
- 可远程缓存。
- 可远程执行。
- 输入输出明确。
- 不依赖系统 PATH 里的 Buf 或 protoc；protoc 由 Bazel toolchain 提供，插件由 `go_binary` 构建并由 toolchain 注入。
- 支持 Bazel Proto 规则生态（`ProtoInfo`）。

### 8.2 API 设计

建议提供一个统一的组合 Rule：

```python
load(
    "@grpc_gateway_typescript//:defs.bzl",
    "grpc_gateway_typescript_library",
)

grpc_gateway_typescript_library(
    name = "user_sdk",
    proto = ":user_proto",
    typescript = True,
    axios = True,
    react_query = True,
)
```

组合 Rule 是用户使用入口，不意味着三个插件必须合并为一个二进制。内部仍然是三个独立的生成 Action。

### 8.3 独立生成能力

```python
grpc_gateway_typescript_library(
    name = "user_types",
    proto = ":user_proto",
    typescript = True,
)

grpc_gateway_typescript_library(
    name = "user_api",
    proto = ":user_proto",
    typescript = True,
    axios = True,
)
```

依赖校验（analysis 阶段）：

- `axios=True` 必须同时 `typescript=True`。
- `react_query=True` 必须同时 `typescript=True` 且 `axios=True`。
- 否则直接报错，不要等到 TypeScript 编译时才发现 import 不存在。

### 8.4 内部设计

基于 `ProtoInfo` 获取 Proto 输入及其依赖：

1. `proto_info.direct_sources`：决定对哪些 proto 调用插件。
2. `proto_info.transitive_sources`：作为 action inputs。
3. `proto_info.transitive_proto_path`：拼 `--proto_path`。
4. 构造 `protoc` 调用：
   - `--plugin=protoc-gen-...=<toolchain 中的插件路径>`
   - `--..._out=<opts>:<输出目录>`
5. 声明输出文件。
6. 通过 `DefaultInfo` 返回生成产物。
7. 通过自定义 provider（例如 `GrpcGatewayTypeScriptInfo`）暴露 `types` / `api` / `query` depset，供下游按需使用。

Action 必须明确声明：

- 输入 Proto 文件。
- Proto import 依赖。
- Plugin 可执行文件。
- `protoc` 可执行文件。
- 其他必要的工具文件。
- 输出文件。

### 8.5 输出声明与稳定产出

- 每个 `file_to_generate` 固定生成三个文件（见 §2.3），因此 Starlark 可以通过 `<base><suffix>` 直接计算输出路径。
- 空文件也生成 header，避免“有 service 才生成 `_api.ts`”导致 Starlark 无法预知输出。
- 如果多个 target 生成同一 proto，输出路径会冲突；建议：
  - 输出放到 target 专属目录，或
  - 文档明确“一个 proto 集只建一个 SDK target”。

### 8.6 Action 并行

v1.0 §8.6 的表述前后矛盾。正确结论：

```
Proto
  |
  +--> TypeScript Generation
  |
  +--> Axios Generation
  |
  +--> React Query Generation
  |
  v
聚合 target（DefaultInfo / 自定义 provider）
  |
  v
ts_project / 其他消费 target
```

三个生成 action 互不读取输出，可以并行；只有最终的 TypeScript 编译需要三者齐全。不要为了表达逻辑层次而制造无意义的串行依赖。

### 8.7 Toolchain

建议使用 Bazel Toolchain 管理插件二进制：

```
grpc_gateway_typescript_toolchain
├── typescript_plugin
├── axios_plugin
└── react_query_plugin
```

要点：

- toolchain type 单独导出；
- 模块自己注册默认 toolchain，用户不需要手写；
- 三个插件通过 `go_binary` 构建，建议 `pure = "on"`，便于远程执行；
- 用户可以覆盖 toolchain 使用自定义构建的二进制。

### 8.8 模块布局

建议拆成：

- `defs.bzl`：规则；
- `toolchain.bzl`：toolchain 定义；
- `extensions.bzl`：模块扩展（可选，用于获取或构建插件）；
- `MODULE.bazel`：声明 `rules_go` / `protobuf` / `gazelle` 依赖并注册 toolchain。

## 9. 生成参数设计

三个插件都支持标准 Protoc 参数格式：

```
--<option>=<value>
```

### 9.1 三插件共享契约参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `types_suffix` | `_pb.ts` | 类型文件后缀 |
| `api_suffix` | `_api.ts` | Axios 文件后缀 |
| `query_suffix` | `_react_query.ts` | React Query 文件后缀 |
| `import_extension` | 空 | 相对 import 追加 `.js` 等 |
| `use_proto_names` | `false` | 字段名使用 proto 原名 |
| `empty_files` | `emit` | `emit` / `skip` |
| `M<proto>=<module>` | 无 | 外部类型模块映射，可重复 |

### 9.2 TypeScript Plugin

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `long_type` | `string` | `string` / `number`（`bigint` 延后） |
| `bytes_type` | `string` | `string`（`Uint8Array` 延后） |
| `enum_style` | `union` | `union` / `const` / `enum` |
| `oneof_style` | `union` | `union` / `flat` |
| `nested_name_separator` | `_` | 嵌套类型命名分隔符 |
| `emit_comments` | `true` | 是否生成 proto 注释 |

### 9.3 Axios Plugin

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `client_style` | `class` | `class` / `functions` |
| `additional_bindings` | `ignore` | `ignore` / `methods` |
| `strict_http` | `false` | 无 `google.api.http` 时是否报错 |
| `streaming` | `ignore` | `ignore` / `error` |

v1.0 的 `use_import_type` 选项移除：生成代码统一使用 `import type`。

### 9.4 React Query Plugin

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `hook_prefix` | `none` | `none` / `service` |
| `request_optional` | `true` | `request` 是否允许 `undefined` |
| `queries` | 空 | 强制作为 Query 的方法列表，逗号分隔 |
| `additional_bindings` | 继承 Axios | `ignore` / `methods` |

v1.0 的 `query_key_prefix`、`query_enabled`、`mutation_style` 语义不清，v1.1 用 `hook_prefix`、`request_optional` 和 Query/Mutation 分类替代。

参数应保持稳定，避免过早引入大量配置项。

## 13. 最终项目交付形态

最终项目提供三个独立的 Protoc Plugin：

```
protoc-gen-grpc-gateway-typescript
protoc-gen-grpc-gateway-axios
protoc-gen-grpc-gateway-react-query
```

以及一套 Bazel 集成：

```
grpc-gateway-typescript.bzl
```

开发者只需要维护 Proto：

```
proto/
└── user/
    └── v1/
        └── user.proto
```

即可生成：

```
gen/
└── user/
    └── v1/
        ├── user_pb.ts
        ├── user_api.ts
        └── user_react_query.ts
```

最终使用方式：

```ts
import axios from "axios";

import { UserServiceClient } from "./gen/user/v1/user_api";
import { useGetUser } from "./gen/user/v1/user_react_query";

const http = axios.create({
  baseURL: "/api",
});

const userClient = new UserServiceClient(http);

function UserPage() {
  const { data, isLoading } = useGetUser(userClient, {
    id: "1001",
  });

  if (isLoading) {
    return <div>Loading...</div>;
  }

  return <div>{data?.name}</div>;
}
```

**最终设计原则：**

- Protobuf 是 API 契约的唯一来源。
- TypeScript 插件只生成类型。
- Axios 插件只负责 HTTP API Client。
- React Query 插件只负责 React Query 集成。
- 插件保持独立，职责清晰。
- 共享 Proto Descriptor 解析、IR、命名和 import 契约。
- Buf 负责多插件生成编排。
- Bazel 负责可复现的构建和依赖管理。

## 14. 已拍板的关键设计决策

| 决策 | 结论 |
| --- | --- |
| 输出粒度 | 每个 proto 三个文件，跨文件用 namespace import |
| 文件后缀 | `_pb.ts` / `_api.ts` / `_react_query.ts`，三插件共享契约参数 |
| 字段命名 | 默认 `json_name`，可选 `use_proto_names` |
| int64 / bytes 默认 | `string` / `string`；`number` 可选；`bigint` / `Uint8Array` 延后 |
| 字段可选性 | 所有 singular 字段 `field?: T` |
| oneof | 互斥联合类型（默认），可回退扁平 |
| enum | 字符串字面量联合（默认），可选 const / enum |
| map | `Record<string, V>`，key 永远是 string |
| Query 编码 | 显式 `URLSearchParams`，保留 0 / false / "" |
| Path 编码 | 单段 `encodeURIComponent`，多段按段编码 |
| response_body | 解包字段并改变返回类型 |
| additional_bindings | 默认只生成 primary；可选 `methods` 生成 `MethodBinding2...` |
| 流式 | v1 只做 unary，默认跳过，可配置报错 |
| 请求取消 | 所有方法接受 `AxiosRequestConfig`，传递 `signal` |
| React Query 注入 | 每次调用传入 client |
| Query Key | 每个 method 一个 key，包含完整 request，service 作用域前缀 |
| Bazel 依赖 | 三个生成 action 并行，聚合 target 统一依赖 |
| 生成代码质量 | 不使用 `@ts-nocheck`，strict 编译 |

## 15. 参考实现对照与取舍

| 维度 | grpc-gateway-ts | typescript-http | 本项目 v1.1 |
| --- | --- | --- | --- |
| 输出粒度 | 每 proto 一个文件 | 每 package 一个文件 | 每 proto 三个文件 |
| 跨文件 import | namespace import | 无（外部类型内联） | namespace import + `M` 映射 |
| int64 | string | number | string（number 可选） |
| bytes | Uint8Array | string | string |
| enum | string enum | string union | string union（默认） |
| 字段可选性 | `?:` | `T \| undefined` / `?:` | `?:` |
| oneof | `OneOf<T>` 联合 | 扁平可选 | 互斥联合 |
| query 方法范围 | 仅 GET | 所有方法 | 所有方法 |
| query 编码 | 部分正确，丢零值 | 较完整，truthiness bug | 完整，保留零值 |
| path 编码 | 无 | 无 | 单段/多段分别处理 |
| body | `*`/字段（嵌套错误） | `*`/字段/嵌套 | `*`/字段/嵌套 |
| response_body | 无 | 无 | 支持 |
| additional_bindings | 无 | 只解析 | 默认 primary，可选生成 |
| 流式 | fetch NDJSON | SSE/WS | v1 不做 |
| 请求取消 | 无 | 无 | 支持 |
| React Query | 无 | 无 | 支持 |
| 生成代码质量 | 默认 `@ts-nocheck` | 固定 `@ts-nocheck` | 不用 `@ts-nocheck` |

可借鉴：

- grpc-gateway-ts：int64 默认 string、namespace import、fetch 流式实现（后续）。
- typescript-http：嵌套 body、map query、`ClientTransport` 抽象（后续）。

不要照抄：

- GET-only query、truthiness 判断、map 点号编码、path 不编码、`@ts-nocheck`。
- package 级单文件 + 外部类型内联（会重复类型、破坏类型同一性）。
- 全局 `seen` 的 query 字段遍历（会漏掉同一类型在不同分支的字段）。

两份参考实现均为宽松许可证（Apache-2.0 / MIT）。如果复制代码片段，需要保留许可证和归属声明。
